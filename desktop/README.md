# Attendance OS — Desktop app

One Mac/Windows/Linux app: **open it → it fetches punches from the device →
shows reports.** The "fetch" is a pull over the device's SDK port (TCP 4370);
punches are saved to Supabase (cloud) so reports also open from anywhere. The
proven always-on **push catcher is bundled as an optional backup.**

```
device (TCP 4370) ──fetch on open──▶ Electron app ──▶ Supabase ──▶ same app shows reports
                                     (dashboard UI)    (cloud)
optional backup:  device ──push──▶ bundled listener (:8081) ──▶ Supabase
```

## ⭐ First: test that "fetch" works on your real device

Pull isn't guaranteed on every ZKTeco firmware (yours was set up for push), so
test it in 2 minutes **on the office PC, on the same Wi-Fi as the device**:

```bash
cd desktop
npm install
npm run sync -- --dry-run        # reads from the device, writes nothing
```

- ✅ Prints “read N record(s) … WORKS” → fetch-on-open is good; the app will use it.
- ❌ Times out / “won’t return attendance logs” → your firmware blocks pull; just
  switch on the bundled **catcher (push)** in the app’s Settings — it’s already
  proven on your device.

To also save what it read: `SUPABASE_URL=… SUPABASE_SERVICE_KEY=… npm run sync`

## Run the app from source

```bash
npm install
npm run bundle:renderer    # builds the dashboard into renderer/
npm start                  # launches the app
```

First launch shows a **Settings** screen — paste your Supabase URL + anon key +
service-role key and confirm the device IP. That's the only setup. After that:
open the app → it fetches → reports.

## Build installers (Mac / Windows / Linux)

Installers are produced by CI, not by hand:

- Push a tag: `git tag v1.0.0 && git push origin v1.0.0` → the
  **Build desktop app** GitHub Action builds all three installers and publishes
  them to a GitHub Release.
- The app then **auto-updates** from those releases (electron-updater). That's
  the "update on command" path: you ask for a change → it's pushed → a new
  release → the app updates itself.

Local one-off build: `npm run dist` (or `npm run dist:linux`). Output in `release/`.

## How it's wired

| File | Role |
|---|---|
| `src/sync.js` | Pull from device (node-zklib) → upsert to `raw_punches` (idempotent) |
| `src/sync-cli.js` | Standalone device test (`npm run sync`) |
| `src/main.js` | Electron main: window, tray, config store, sync-on-open, optional push fork, auto-update |
| `src/preload.js` | Secure bridge — injects config + `syncNow()` into the renderer (no secret key exposed) |
| `renderer/` | The dashboard build (generated by `bundle:renderer`) |
| `electron-builder.yml` | Packaging + GitHub publish config |

The renderer is the same React dashboard in `../dashboard` — it just reads its
Supabase config at runtime (from Settings) instead of from a `.env`.

## Notes

- **Fetch needs the office Wi-Fi** (to reach the device). Viewing reports works anywhere.
- Data is as fresh as your **last open/sync** — fine for reports, not a live ticker. (Turn on the push backup if you want true real-time.)
- Installers are **unsigned** unless you add Apple/Windows signing certs — expect a one-time "open anyway" prompt.
- The service-role key is stored locally by the app (Electron `userData`) and never exposed to the web page.
